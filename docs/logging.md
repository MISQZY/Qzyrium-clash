# Журнал и файлы логов

Файлы находятся в `logs` внутри каталога данных приложения. Текущая запись
ведётся в `latest.log`. Непустой файл архивируется при следующем запуске,
смене дня по UTC или перед превышением 10 МиБ. Имя архива соответствует
времени последней записи файла: `2026-11-10T12-34-56-789Z.log` (UTC).
При совпадении имён добавляется числовой суффикс, существующий архив сохраняется.

Хранятся до 20 архивов не старше 30 дней. Очистка выполняется при запуске
и ротации; посторонние файлы не удаляются. При первом запуске новой версии
старые `qzyrium.log` и `qzyrium.log.1` переносятся в тот же формат архивов
и далее подчиняются общим ограничениям хранения.

Каждая строка содержит время ISO 8601, уровень и источник (`app` или `mihomo`).
Многострочные ошибки сохраняют отступы; очень большие сообщения разбиваются
с сохранением UTF-8 и лимита размера файла. Ошибки файловой системы выводятся
в консоль и не завершают приложение. Файлами управляет только экземпляр,
получивший блокировку единственного экземпляра Electron.

Журнал в интерфейсе показывает события Mihomo из stdout/stderr: запуск,
работу и остановку ядра. Параллельный поток логов WebSocket не используется,
чтобы не дублировать события. Логи продолжают сохраняться на диск, когда окно
скрыто. Подробность вывода определяется настройкой уровня логов ядра.

В интерфейсе время показывается в местном часовом поясе с миллисекундами;
полное исходное время доступно при наведении. Есть фильтр уровня и поиск
по тексту. Кнопка очистки очищает только буфер журнала в интерфейсе;
файлы на диске сохраняются. Лимит записей интерфейса задаётся в настройках.

Проверки: `pnpm test:logs`, `pnpm test:kernel`, `pnpm test:ui` после `pnpm build`.
