Linux container network probe

Run: pnpm test:network:container
Requires a running Linux x86_64 Docker daemon with /dev/net/tun support.

Scope: the production Linux core supervisor with the real pinned Mihomo core,
explicit HTTP proxy traffic, TUN stacks gvisor/system/mixed, DNS, SIGTERM/SIGKILL,
parent SIGKILL, and IPv4/IPv6 policy rules after exit. All 12 cases must pass.
This does not test Electron, the Windows native watchdog, Windows registry proxy
restoration, or the Windows TUN driver. No user subscriptions are loaded.

The test creates a temporary Docker bridge and a controlled HTTP CONNECT/DNS
peer. Each case gets a separate network namespace and NET_ADMIN plus /dev/net/tun;
it does not use privileged mode or host networking. Only generated fixture files
and a results directory are mounted. The test removes its own containers and
network at the end. Logs, routing snapshots and report.json remain under
artifacts/container-network/run-*/.

The Python and Node images are pinned by digest; the Linux Mihomo binary is
verified against scripts/resources.lock.json. Missing pinned images/archives may
be downloaded. The supervisor is copied directly from resources/, the same source
shipped with the application, rather than implemented by the test.

Exit code 1 means a case failed, including leftover policy rules even when HTTP
and DNS connectivity have recovered. This test is opt-in because it needs Docker.

Observed with Mihomo v1.19.33 and Docker Desktop Linux/WSL2:
- With the supervisor: SIGTERM, core SIGKILL and parent SIGKILL restore the
  baseline. A separate policy rule at priority 12000 remains untouched.
- The mixed-stack case uses custom table/rule indexes to verify those settings.
- To reproduce the original failure without the supervisor, run:
  node scripts/check-container-network.cjs --raw
  Bare Mihomo still leaves policy rules after TUN SIGKILL; this control must fail.
- Optional filters: --mode=gvisor --termination=SIGKILL.

Linux runtime requirements: the ip command and the bundled Node supervisor.
The app launches the supervisor through Electron's Node mode, so standalone Node
is not required on the user's machine. pnpm prepare:resources installs the helper
for Linux development; packaged builds include it as an external resource.
TUN startup refuses occupied rule priorities/tables. Cleanup removes only the
known Mihomo rule shapes in the reserved range and never flushes a routing table.

These Linux results do not establish that Windows has the same failure mode.
